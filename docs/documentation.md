## Overview

xcalygraph is a single-binary CLI for AI agents. It turns any directory (code repository, server filesystem, document corpus) into a dense, agent-readable knowledge graph plus precomputed analyses, so an agent gets verified structural context with few tokens and little orchestration work. It ships with one compact agent skill that the binary installs and updates together with itself.

It is a clean-room rewrite of a selected subset of Graphify, without LLM calls, without visualization, without runtime dependencies and optimized for build speed, incremental updates and token efficiency of its output. Target blueprint: `docs/spec.md`; deferred features: `docs/deferred.md`.

License: MIT (`LICENSE`).

- Rust symbol-level test facts and run filters identify explicitly attributed test functions; calls through helpers remain traversable, and test functions do not appear as production `map` entrypoints. Test-file and `#[cfg(test)]` filtering still includes helpers.
- Search also looks up related query-only forms (`validation`/`validate`, `token`/`tokenize`, `retrieval`/`get`) at half the original term's weight. Exact terms remain indexed and are never replaced; the higher contribution per query term is used.
- Query flags: `-C, --root PATH`, `-b, --budget N` (tokens, bytes / 3), `--json`, `--read-only`, `--index-dir PATH`, `-p, --path GLOB` (gitignore syntax, repeatable), `-l, --lang LIST`, `-k, --kind LIST`, `--exact`, `--no-tests`; `show` adds `-d, --depth N` and `--all`. One inclusion rule (`Filter::includes`, `src/app/query/mod.rs`) governs every stage: NAME resolution in all forms, `path` hops (induced subgraph), `impact` dependents, tests and run lines (traversal itself crosses excluded nodes), `show` tests and `map` module sections; `-k` limits symbols only, so files stay resolvable. Text output doubles backslashes, writes LF/CR/TAB as `\n`, `\r`, `\t`, and encodes other C0/C1 controls as four-digit lowercase hexadecimal `\uNNNN`; escapes are reversible and budgeted by rendered UTF-8 bytes.
- NAME forms: `qualified.name` or `qualified::name`, a qualified suffix (`Store.Get`), `path:line` (innermost symbol containing the line), `path::name`, a file path, or a bare name. A file-path match wins a locator collision, including through the existing `./` alias; xcalygraph checks the input spelling first, then its surrounding-whitespace-trimmed form before locator syntax.
- Proven compatible top-level or reopened same-path TypeScript interface declarations in one file are one logical type for lookup, search, context, paths, impact and audit. Within the same proven `tsconfig.json` project, global-script interfaces and `declare global` contributions at the same namespace path also merge when their complete headers and supported members are compatible; imports can add excluded local TypeScript files to that project. `show` keeps every physical declaration, path, line, field and method. External modules, declaration-file pairing, incompatible parts and unproven project or scope evidence remain distinct.
- Use `exact symbol NAME` in a `find` or `ctx` query when semantic alternatives are unsafe. The case-insensitive cue resolves a bare or qualified symbol name exactly and returns exit 4 when absent; `ctx` may add related graph context after the exact hits.
- An empty answer says what it proves: `show` and `impact` of a symbol without references print `! no static reference in the repository; complete analysis` (`, exported` when outside use is possible), or that ambiguous references or incomplete files leave absence unproven; a `find` miss names what was searched.
- Relation lines of `show`, `impact` and `path` print a symbol's name without its module part and `path:line`, or `:line` right after a line of the same file; every printed `path:line` works as NAME and JSON keeps the qualified name. Mean output on the sampled public-corpus `show` and `impact` answers fell 21 % with the same facts.
- Query commands refresh the index first; `--read-only` never creates, probes or writes anything under the root, HOME or index base (also for a non-writable index) and exits 5 whenever a rebuild would be needed: index missing, sources changed, derived image corrupt, required `impact --diff` facts missing or inconsistent with source hashes, or another extraction, resolver or binary version.
- Exit codes: 0 answer, 1 runtime error, 2 usage error, 3 ambiguous NAME (candidates on stdout), 4 no match, 5 index missing or stale under `--read-only`.
- Usage errors print one stderr line `xcalygraph: <error>; run 'xcalygraph help'` and nothing on stdout. A reader that closes stdout early (`| head`) is not an error.
- Analysis coverage: every file has a status (complete, parse errors, match limit, no grammar, failed, unreadable). `! coverage: N of T files incomplete (classes): p1 p2 p3 +M; absence unproven` appears in `audit` whenever a filtered file is incomplete, in `show` for a symbol without incoming edges and in `impact` without dependents (only files of the target's language family count), and in `map` for match limit or worse. Complete repositories print nothing; JSON uses a `note` record.

## Languages

Every language drops unqualified references to its builtins and prelude names, unless the file defines a function of that name at top level or in a module (a local definition shadows the builtin; methods of classes do not). Locals and parameters shadow every unqualified use of their name in their scope (Ruby: only bare names, since `foo(1)` calls the method). Member reads with a declared receiver type resolve to the member (`account.label`, method values like `read := rw.Read`). Overloads of one owner, including top-level functions of one module or imported module (Kotlin, C++, Dart), are told apart by argument count (trailing lambdas count as one argument; string defaults may hold commas); several overloads accepting the count are all targets, inferred. Swift overload calls compare external argument labels in source order; only parameters with defaults may be omitted, while calls with trailing closures retain argument-count matching. Objective-C message sends use the complete selector, and `@selector(...)` references match that selector with inferred confidence because they have no receiver type. Signatures longer than 160 characters keep their whole parameter list with each parameter shortened to its label and name (`columns = …` marks a default), so the count survives. Base lists record their type argument count, so a base type named like a generic overload (`IRequest` and `IRequest<T>`, `Base` and `Base<T>`) resolves to the overload with that many type parameters.

JavaScript and TypeScript class expressions do not produce class nodes or heritage edges attributed to an enclosing symbol; named class declarations retain their heritage edges.

Attributes, inherited requirements, decorators and dynamic class bodies are not inferred; this is not a full Python type check.

TypeScript interface cards include direct identifier-named properties, with valid Unicode escapes decoded to their identifier value, including optional and readonly properties, simple unescaped alphanumeric, `_`, `$` and `-` string keys, and canonical safe-integer keys. Direct flat unions and intersections of named source types on interface and class fields are preserved for receiver method calls: every union arm must prove the member, while any intersection constituent may provide it. Missing or ambiguous type names, optional fields and unsupported forms, including arrays, tuples, parenthesized or nested combinations, remain unresolved; this is not a general TypeScript type checker. Same-file declarations merge when complete source evidence proves member compatibility, including supported string and number index signatures with assignable member values. Type names resolve through their enclosing lexical scopes before file-level declarations and imports; unrelated nested types are not visible. Generic parameters that may shadow a name prevent guessing a concrete type. Nested object members, computed keys and other literal-key forms are not treated as direct properties of the enclosing interface; a syntactically erroneous interface yields no property facts.

Resolution order for all of them is `docs/spec.md` section 6: lexical scope, imports, qualified names, same module, member calls through receiver types (self, declared bindings, constructor and call results, field chains), interface dispatch to non-test implementations (inferred, max 10), overloads narrowed by argument count (the single overload taking the count is exact, several are inferred), unique-name fallback within the own and imported modules for every language (root-wide only for languages without module rules), inferred, else an ambiguity count. Python calls use the latest same-module definition available at runtime; function-body global lookup is inferred, module- and class-body lookup uses the latest definition before the call. Python methods whose complete executable body is an optional docstring plus `raise NotImplementedError` dispatch to known local concrete overrides (inferred, max 10); no known override stays unresolved. Calls with unresolved receivers do not use unique-name fallback for member names common on builtin types such as `get` or `match`. JavaScript and TypeScript class-value calls select static methods, while instance receivers select instance methods. A qualifier chain whose head is an external import (`std.heap.ArenaAllocator.init`) stays external. Test symbols are targets only for test callers.

## Installation and releases

- Install script: `scripts/utils/install.sh`, attached to every release as `install.sh`, resolves the latest release (or `--version X.Y.Z`), downloads the platform archive and `SHA256SUMS`, verifies the checksum, smoke-tests the binary and lets it run `install` (binary, skill, Claude Code link); `--no-skill` installs only the binary through an exclusively created temporary file beside the destination, preserves existing temporary entries and rejects directory targets; `XCALYGRAPH_INSTALL_DIR` and `XCALYGRAPH_RELEASE_BASE` (also `file://`) override target and source.
- Progress: `install` and `update` draw their phases on stderr when it is a terminal (`src/app/progress.rs`: spinner with elapsed time, download bar in eighth blocks with bytes, smoothed speed and remaining time, one line per finished phase with paths below HOME shown as `~`); otherwise nothing is drawn and the stdout result lines carry the facts.
- Release archives: `scripts/build/build-release.sh [TARGET...]` builds `dist/xcalygraph-<version>-<os>-<arch>.tar.gz` (binary, `LICENSE`, `THIRD-PARTY-LICENSES.txt` with top-level regular `LICENSE*`, `COPYING*` and `NOTICE*` files and Cargo-declared license files from dependencies) and `dist/SHA256SUMS`. License paths retain control characters; discovered symlink files are skipped, declared paths containing symlinks are rejected, and missing or unreadable files abort staging. A declared file already found by discovery is included once. Builds and staging in a temporary directory under `dist` use the checkout-owned Cargo target under the source guard; final archive and checksum names are installed only after its final source check succeeds. The version is rechecked inside the guard. The script preserves unrelated entries, rejects an occupied archive or checksum path and includes only this build's archives in the checksum file. Before touching `dist`, it checks for Bash, Cargo, Git, jq, Python 3, rustc, awk, tar and either `sha256sum` or `shasum`. If local publication fails partway, already published outputs remain and the failure is reported. `scripts/tests/test-release-provenance.sh` exercises the same staging and local-output path with debug fixtures, including missing-tool preflight, source changes, interruptions and concurrent builds; `scripts/tests/test-release-licenses.sh` verifies unusual and declared license paths in a debug archive.
- `.github/workflows/release.yml` builds darwin-arm64, darwin-amd64, linux-amd64, linux-arm64 (static musl) on a `v*` tag and publishes them with `SHA256SUMS` and `install.sh` as the release of that tag. Before the gate, the workflow uses `scripts/utils/validate-release-tag.sh TAG CARGO_VERSION` to require `GITHUB_REF_NAME` to equal `v` plus the Cargo package version; `scripts/build/build-release.sh` repeats the check before creating `dist`. This makes Cargo-version archive names match installer and updater names derived from the release tag. Both Linux build runners install Ubuntu's `hyperfine`, `jq`, `musl-tools`, `pipx`, Python 3, `rsync`, ShellCheck and `tar` packages; the x86_64 Linux gate additionally installs upstream-pinned `graphifyy==0.9.97` in an isolated pipx environment. The gate checks the Graphify CLI version against the local upstream reference; no hosted workflow run is implied by local checks.
- `.github/workflows/ci.yml` runs the product gate (`scripts/tests/test.sh`) on Ubuntu for every push to `main` and every pull request, with the tools the gate's own `--all` fixture test needs.
- Update trust: `install.sh` and `update` verify the archive against `SHA256SUMS` from the same release. This detects transfer corruption and mismatched assets, not a compromised release or account; the archives carry no publisher signature.
- Versioning: every index-format or skill change raises the minor version in `Cargo.toml` (the skill version equals the binary version), so `version` and `update` identify the state.

### Release installer

The one-line installer fetches `install.sh` from the latest [release](https://github.com/Christopher-Schulze/xcalygraph/releases), never from `main`. It:

- picks the archive for your platform (macOS and Linux, arm64 and x86-64);
- verifies it against the release's `SHA256SUMS`;
- smoke-tests the new binary before it replaces an existing one;
- lets the binary install itself, the skill and the Claude Code link;
- reports a missing PATH entry with the exact `export` line instead of editing your shell profile.

```bash
# a specific version, or the binary without the skill
curl -fsSL https://github.com/Christopher-Schulze/xcalygraph/releases/latest/download/install.sh | bash -s -- --version X.Y.Z
curl -fsSL https://github.com/Christopher-Schulze/xcalygraph/releases/latest/download/install.sh | bash -s -- --no-skill
```

`XCALYGRAPH_INSTALL_DIR` changes the target directory (default `~/.local/bin`).

### What `xcalygraph install` does

```bash
xcalygraph install               # binary, skill, Claude Code link
xcalygraph install --skill-only  # skill (and link) only
xcalygraph install --no-link     # no Claude Code link
```

- **Binary**: copies the running executable to `~/.local/bin/xcalygraph` unless it already runs from there.
- **Skill**: writes the embedded skill to `~/.agents/skills/xcalygraph/SKILL.md`, the shared location agent hosts read. The skill always matches the binary's version.
- **Claude Code**: when `~/.claude` exists, links `~/.claude/skills/xcalygraph` to that directory. A foreign file or link there is reported and never replaced.

### Update

```bash
xcalygraph update           # newest release, then a fresh skill
xcalygraph update --check   # only report whether one is available
```

`update` downloads the release for your platform, verifies the checksum, smoke-tests the new binary, replaces the old one atomically and installs the matching skill. When the binary is already current, it still rewrites a skill that is out of date. On a terminal every step shows live progress (download bar with speed and remaining time); in scripts and agent runs only the result lines appear.

### Uninstall

```bash
xcalygraph clean                # every index
rm ~/.local/bin/xcalygraph
rm -r ~/.agents/skills/xcalygraph ~/.claude/skills/xcalygraph
```

## Output format

- Field lists in `show` use comma-separated names. After decoding the text or JSON transport, names requiring disambiguation are JSON-quoted strings; `\u` escapes preserve unpaired UTF-16 surrogates. Ordinary names remain unquoted.
- TypeScript interface numeric keys use ECMAScript Number values and property-key spelling. Decimal literals with more than 20 significant digits are omitted when permitted implementation-dependent rounding choices yield different numbers.
- Symbol lines are grouped under their file line and indented two spaces: `<line> <signature>`, or `<line> <kind> <name>` for symbols without a signature; `ctx` seeds append ` // <doc sentence>`.
- Bash `option` symbols are named `-x`; the symbol line is the literal `getopts` line, with `arg=none|required;case=<line|*:line|none|ambiguous>` as its signature.
- Relation lines: `<marker> <qualified name> <path>:<line>`; incoming edges cite the reference line, outgoing ones the target definition; edge kinds other than calls and type hierarchy are appended (`uses`, `imports`); a trailing `?` marks an inferred edge. `path` marks each inferred hop (inferred edge or reversed direction) and prefers the equally short path with fewer inferred hops; `impact` marks a dependent inferred unless a shortest chain to a target is all exact, so uncertainty carries to every later depth; `--exact` drops both, and `path` then never falls back to an undirected route.
- `impact --diff` matches definitions by file, package, kind, lexical parents and receiver before considering evidence-backed cross-file moves; duplicate names in unrelated files do not by themselves hide a removal.
- Budget: stdout never exceeds `3 x -b` bytes, including truncation, ambiguity candidate lists (at most 600 tokens) and `impact` run commands (reserved before notices and changes, package-level form when the precise one does not fit). Truncation ends with `+<n> more` or JSON `{"t":"more","n":<n>}`; if that cannot fit, text uses `+<n>` or `+`, JSON uses `{"t":"more"}` or `{}`. An empty JSON object always means truncation. Grouping never lets a lower-ranked hit displace a higher-ranked one: the best hits that fit are chosen first, then grouped.
- `--json` writes JSON Lines with the fields of `docs/spec.md` section 8; empty fields are omitted.
- Map JSON keeps file/symbol counts, task targets, API signatures and handlers, cycle/layer members, and environment read locations in typed fields. Audit JSON keeps finding names, source paths and lines separate; drift records also expose direction and status.

## Architecture

Single binary crate. Layers and modules under `src/`:

| layer | modules | responsibility |
|-------|---------|----------------|
| `cli` | `cli.rs` | argument parsing, help text, exit statuses |
| `app` | `app/` | one use case per command: workspace resolution, refresh pipeline, queries (`app/query/`) |
| `domain` | `domain/` | pure model: file types and roles, corpus records and change detection, facts, graph, tokenizer |
| `extract` | `extract/` | pure fact extraction: generic tree-sitter query engine (`engine.rs`), one language pack per grammar (`lang/`, queries in `queries/*.scm`), manifests |
| `resolve` | `resolve/` | pure global resolution of all facts to the symbol graph (`mod.rs`: resolution order steps 1 to 8, implementations, dispatch; `modules.rs`: module maps; one module per language family: `rust`, `go`, `python`, `js`, `typescript`, `typescript_groups`, `jvm`, `dotnet`, `cfamily`, `julia`, `imports` for the smaller languages) and derived data (`derive.rs`: rank, module import graph, cycles, layers) |
| `infra` | `infra/` | parallel walk, scan and hashing, writer lock, index store (container, codec, fact shards, zero-copy `derived` file) |

`src/main.rs` wires the layers and owns process IO: stdout, stderr and the exit code.

Refresh pipeline: lock -> walk (`ignore` crate, parallel) -> stat diff against the file table (an unchanged `.h` whose C++ sibling appeared or vanished is reclassified, the only classification input outside a file; checked by binary search in the sorted file table) -> read, hash, classify and extract candidates from one buffer (parallel, each source read once; a parser fault is isolated per file, which keeps its path and coverage status `failed`; a permission-denied source is classified by path and recorded `unreadable`, other read errors abort the refresh) -> rewrite only the affected fact shards -> resolve all facts -> write `derived` -> write file table and meta. Writers reject symlinked or hard-linked lock files; an existing regular lock is opened without creation or truncation and verified before use. The lock is advisory and cannot protect against processes that disregard it. An empty change set writes nothing. `derived` is rebuilt when content changed, when its header is invalid, or when it was written by another binary or resolver version; a checksum or content failure found by a query or `index` re-derives it once from stored facts. Equal headers and lengths do not suppress a write unless the existing image is byte-identical. When rebuilding `derived`, missing, corrupt, incomplete or source-hash-mismatched required fact shards are re-extracted from their source files; writable `impact --diff` uses this locked recovery path and retries, while read-only reports stale without writing. Walk and read errors or content changes during extraction abort the update. Before changing shards, the writer invalidates metadata so interrupted updates force a rebuild instead of mixing generations. Each language query compiles lazily, only when a file of that language is extracted.

Freshness compares size and mtime together with device, inode and status-change time on Unix; both times must be outside the two-second racy window. Missing or unusable identity forces content-eligible files to be hashed; sensitive and oversized files remain path-only. This detects ordinary edits and replacements that restore mtime, but metadata cannot prove freshness if a filesystem repeats or rewinds its identity and status-change values, and a scan does not freeze concurrent source edits.

Index location: disposable by design (`src/app/workspace.rs`; building a new index in the default base also removes verified indexes whose root is gone, and each writing refresh removes temporary files of killed writers): `--index-dir`, else a nonempty `$XCALYGRAPH_INDEX_DIR`, else `<system temp directory>/xcalygraph-<user>` (new base mode at most 0700), so the operating system's temp cleanup bounds their number and repositories stay clean. No temporary writability probe is created: an existing shared index works even when its base cannot create entries. If implicit shared-index preparation or a required write fails because of its location, the index goes to `<root>/.xcalygraph/` with a notice to ignore it in git; explicit locations, source errors and lock contention do not fall back. Both implicit index locations are excluded from the walk. Read-only discovery writes nothing and can use a current local index when the shared one is absent, stale or unreadable. A lost index costs one full build; shards are extracted, deflated and written in parallel. Index files (`<index-dir>/<root name>-<hash>/`): `meta`, `files` (front-coded paths, stat, XXH3-128, role, file type), `facts/00..63` (varint-coded per-file source hashes and facts with sparse Swift/Objective-C and exported top-level TypeScript callable identities, referencing a shard-local string table; both sections deflated; shards are inflated in parallel when `derived` is rebuilt), `derived` (fixed-size records cast in place from the memory map: string table, files, symbols with rank (qualified names stored as a shared prefix string plus the name), forward and reverse CSR adjacency, modules, module import graph, externals, env sites, fields, type members, stale doc references, ambiguous names; search postings with per-field term frequencies as delta-varint pairs, decoded per query term), `git` (churn and co-change of the last 1000 non-merge commits, with NUL-delimited UTF-8 paths, keyed by HEAD and analysis version, written on the first `audit` after either changes). Every file carries a header with magic, format version, kind and XXH3-64 checksum and is replaced by temp file plus rename.

Top-level TypeScript interfaces and exported namespace interfaces retain complete source-token headers and supported member identities in fact shards. TypeScript files also retain parse completeness, source module-syntax evidence, and supported `declare global` interface identities with namespace ancestry. `tsconfig.json` facts retain validated project-membership and compiler-scope options, while `package.json` facts retain `type`; the resolver consumes these facts to prove file membership and module scope. Within that proven project scope, compatible global-script and `declare global` contributions with the same namespace path share a sparse group identity in a validated derived-index section; physical declarations remain addressable. Relative local imports add their resolved TypeScript files even when excluded from direct inclusion. Top-level exported functions in `.d.ts` pair with a unique `.ts` or `.tsx` implementation only when resolver module identity, callable kind and complete normalized signature-token identity match; normalization ignores formatting and comments and removes only the terminal declaration semicolon. Both physical symbols remain searchable, while unproven overloads and other unsupported declarations remain distinct. External modules and unsupported project configurations remain distinct. Supported equivalent identifier, string-literal and numeric-literal property keys use their canonical key identity while retaining complete type and modifier tokens; valid Unicode escapes in bare identifier keys use their decoded value, malformed escapes are omitted, and escaped declaration names that may denote a matching group, base or type argument prevent a merge. For private declarations in external modules without export clauses or expressions, uniquely declared private nongeneric local interface bases, including distinct, multiple and transitive bases, are supported when overlapping properties have identical signatures and overriding methods include every inherited signature; matching method signatures across bases must be identical. Private generic local bases, including multiple and transitive bases, are supported when all declarations have the same base application, their parameters receive simple local type or primitive arguments or simple defaults referring to those types or earlier parameters, any constraint equals its argument and default after substitution, and their properties use parameters as direct types or array elements. A single direct exported nongeneric base imported from another TypeScript file is supported when all indexed TypeScript files parse completely, embedded-component files and other same-module declarations of either type are absent, the declarations have identical plain base headers and their members do not overlap the imported base or its supported augmentations. Direct relative module augmentations with uniquely resolved exported targets and mutually disjoint supported members join the original interface with their source locations; unsupported or global augmentations prevent this proof. Verified direct-type bindings support inherited field lookup without relocating the original field. Cyclic, unsupported or otherwise unproven inheritance remains distinct, and matching headers alone do not establish a merge. Member and field lookup for a verified group traverses its transitive bases; generic base names are recorded as inheritance references.

For that generic proof, inherited declarations must have disjoint member names, and constrained bases reached through an enclosing type parameter remain unproven; generic methods and complex substitutions also remain distinct. Augmented field types resolve through the original module's directly exported types or the augmentation file's scope; qualified names and other potentially relevant export forms remain unproven.

Grammars are cargo features (`lang-go`, `lang-rust`; all on by default). Adding a language means a pack in `src/extract/lang/`, a query file and fixtures; the engine and resolver are shared.

## Build and test

Build:

- Toolchain: `rust-toolchain.toml` pins Rust 1.99.1 with rustfmt and clippy; `Cargo.toml` sets `rust-version` to the same release.
- Profiles: debug (`cargo build`) for the edit-test cycle, with `xxhash-rust` at optimization level 3 so index integrity checks stay fast; release for the installed binary and measurement harnesses. The release profile is Cargo's default: fat LTO, one codegen unit and strip measured no gain.
- Lints: clippy denies `unwrap_used`, `expect_used`, `panic`, `todo` and `unimplemented` for all targets; tests return `Result` instead of unwrapping.
- Build disk preflight: `scripts/utils/check-build-space.sh [MIN_BUILD_KIB]` checks the Cargo target, intermediate build directory and `/` before each script build: 2 GiB reserve plus the largest of 4 GiB, the existing directory sizes and the requested minimum. If space is short it cleans this package once, then aborts.

Gate:

- `scripts/tests/test.sh` (about two minutes) rejects an inherited `XCALYGRAPH_BLESS`, isolates HOME, temporary paths and Git settings, prunes the cache, then runs Rust format, warning-denied checks for no features and the Bash-only, JavaScript-only and TypeScript-only builds, clippy, tests and the debug build. It needs Git and Python 3 in addition to the Rust toolchain and resolves the physical checkout spelling, so case-insensitive path aliases pass.
- `scripts/tests/test.sh --all` adds ShellCheck over `scripts/` and the script regressions under `scripts/tests/` (cache, corpus, evaluator, benchmark, release and publication tooling); it also needs Graphify 0.9.97, ShellCheck, Hyperfine, jq and rsync. Run it when `scripts/` changes and before a release (the release workflow does; `.github/workflows/ci.yml` runs the plain gate on every push).
- Source guard: `scripts/utils/verification-source.sh` (with `verification-target.sh`, `verification-lock.sh`, `guard-benchmark.sh`) keeps verification artifacts in an ownership-checked target keyed by the checkout path and rebuilds when any tracked, nonignored or `src/`, `tests/`, `skills/`, `.cargo/` file changed by content, including edits that restore mtime or that only a build script reads. Cooperating gates, benchmarks and release staging serialize on its lock; inherited Git routing overrides are removed. `scripts/utils/cargo-artifact.sh` selects the executable Cargo reports; `capture-benchmark-binary.sh` keeps a verified private copy for a benchmark run.

Tests:

- Unit tests live next to the code in `#[cfg(test)]` modules; end-to-end tests of the binary (stdout, stderr, exit codes) in `tests/`. Fixtures are created exclusively under `.cache/` (`tests/support/mod.rs`); subprocesses isolate HOME, temporary and configuration paths and clear inherited Git, xcalygraph and shell overrides.
- Golden fixtures: `tests/fixtures/languages/<id>/` holds sources whose extracted facts are compared with `<file>.facts`; `tests/fixtures/resolve/<case>/` holds small roots whose resolved edges are compared with `<case>.edges`. `XCALYGRAPH_BLESS=1 cargo test` rewrites them; check every changed line against the fixture source before committing. A determinism test compares `derived` images built with 1 and 8 threads.
- Coverage: `scripts/tests/measure-coverage.sh [--missing]` reports line coverage of `src/` without test-only code and development tools (needs cargo-llvm-cov and the llvm-tools component).

Development cache and control plane:

- `scripts/utils/prune-cache.sh [AGE_HOURS]` (default 24, run by the gate) removes aged, completed benchmark, depth and evaluation runs carrying the exact `.xcalygraph-disposable` marker; unknown entries, symlinks, interrupted runs, snapshots and anything containing `.keep` stay. The 3 GiB threshold is a warning.
- Evidence compaction: the same script keeps the newest two runs in `.cache/evaluation/`, `.cache/task192-manifests/` and `.cache/edge-oracle/` whole and reduces older ones, including `.keep` runs, to their top-level regular files up to 8 MiB (reports, identities, summaries, ledgers), marked `.compacted`; a run containing `.keep-full` (for example the reused Graphify baseline `sealed.et38qlb2`) stays whole.
- Control plane: agent rules, owner goals, TASK files, decisions and private benchmark inputs are gitignored here; `scripts/utils/sync-control-plane.sh [MESSAGE]` commits them into a separate Git directory `.control.git/` (gitignored) and pushes it to a private repository configured as its `origin`.
- Publication check: `scripts/audits/check-publication.sh [RANGE]` runs before every push and fails on tracked local-only files, absolute home paths and private names (extended regexes in the gitignored `scripts/audits/private-patterns.txt`) in the tree or message of each commit; RANGE defaults to the commits not yet on `origin/main`. It reads raw bytes of blobs and stored symlink targets; it does not unpack archives or descend into submodules.

Inputs:

- Public corpora: `scripts/utils/sync-corpora.sh [NAME...]` checks out the commits pinned in `scripts/benchmarks/corpora.tsv` (name, URL, commit, languages) into `research/corpora/`. Private corpora are `name<TAB>path` lines in the gitignored `scripts/benchmarks/questions/private/corpora.tsv`, read through `scripts/utils/read-private-corpus.sh`.

The identity records paths, SHA-256 contents and executable bits; Graphify reuse also verifies package source, version, update mode and graph checksum.

Measurements (seconds to minutes; every run keeps identities and raw observations under `.cache/`):

- Query cost: `scripts/benchmarks/measure-query-cost.sh [--patterns] ROOT` reports parse, query compile and match time per language pack and, per pattern, what disabling it saves. A pattern rooted at a container (`(program (...))`) keeps a match open across every child of every container, so such patterns are rooted at the declaration and check the container with `(#parent? @capture "kind" "grandparent kind")`, evaluated in `src/extract/engine.rs`.
- Supply chain: `scripts/audits/check-supply-chain.sh` verifies the vendored grammar's checksums and runs `cargo deny` (`deny.toml`: licenses, sources, advisories) and `cargo audit`, both developer tools; run after every dependency change and in the release workflow.
- Allocations and stage times: `scripts/benchmarks/measure-allocations.sh [--times] ROOT` prints allocations, bytes, live heap and milliseconds per pipeline stage of a full build (`alloc-stats` feature); `--times` builds with `stage-stats` instead, because the counting allocator distorts parallel stages.
- Edge oracle: `scripts/benchmarks/measure-edge-oracle.sh CORPUS...` judges every emitted `calls`, `uses`, `tests`, `inherits` and `implements` edge from an indexed source file against a compiler index (SCIP from scip-go, rust-analyzer, scip-python, scip-typescript; development tools only, default location `~/.local/share/scip-tools` plus PATH) built over the same `git archive` tree. An edge is correct when the compiler resolves a reference on its line to the target (same file and name, definition within 5 lines; constructors count as their class) or, for inherits/implements, when the declared source type has that relationship; inferred edges also count when the compiler names a same-named declared method (dispatch), so inferred precision is an upper bound. Incorrect means the compiler resolves other in-repo targets there; unknown means it reports none, has no symbol for the target (local functions, CommonJS export objects), names only modules there, or, for calls, resolved neither a call nor the target name on that line (untyped parameters such as pytest fixtures). Recall counts distinct source-file/target pairs the compiler references (callables and types; accessors excluded) that have an edge, because edges are deduplicated per source symbol and target. Output: `.cache/edge-oracle/run.*/summary.tsv` plus per-corpus verdicts and missed pairs.
- Sealed retrieval evaluation (under a minute at one budget): `scripts/benchmarks/run-evaluation.sh --set sealed --phase development --budget 600 --reuse-graphify RUN`; run from the canonical checkout spelling. `scripts/benchmarks/questions/sealed/manifest.json` binds eight public source snapshots to 30 questions each; JSON Lines cases name required declaration locators with evidence hashes, negative cases ask for symbols verified absent. `evaluate-sealed.sh` measures actual `find` and `ctx` text and JSON answers and Graphify's (`--reuse-graphify` reuses a completed run's checked raw answers): file hit@5, definition coverage at five and anywhere, multi-location completeness, false positives on negatives, bytes and estimated tokens. `workflow-*` picks `find` or `ctx` from the labels, so it does not measure command choice. `--validate` checks inputs without querying; a run without `--phase development` records the one-time final observation. The same author wrote code and labels, which the report states.
- Legacy evaluation: `scripts/benchmarks/run-evaluation.sh [--no-upstream] [--set NAME] [CORPUS...]` answers `scripts/benchmarks/questions/<corpus>.tsv` (question, expected `path::name`; private sets under `questions/private/`) and reports hit@5 of `find` and `ctx`, tokens per answer, the rg baseline and the upstream Graphify baseline on the same verified snapshot. No-match and ambiguous exits score as misses; runtime failures invalidate the run.
- Performance: `scripts/benchmarks/run-benchmarks.sh [--upstream] [CORPUS...]` builds the release binary and reports per corpus files, full build ms, peak RSS, warm freshness ms, single-file refresh ms, index KB and KB rewritten by a single-file change; the refresh edit appends a newline to a file with extracted symbols in an isolated copy. `--upstream` adds Graphify's numbers on the same snapshot.
- Query compute: `scripts/benchmarks/measure-query-compute.sh ROOT QUESTIONS.tsv [SAMPLES]` measures in-process `find` and `show` wall time (median, p95, maximum), excluding process start, freshness and index opening. `XCALYGRAPH_BENCH_OPT_LEVEL=3` optimizes the project crate in the test profile; neither configuration is the actual release binary.
- Focused comparisons: `measure-symbol-copy.sh DERIVED` (symbol section copy scale), `measure-index-validation.sh SNAPSHOT BEFORE_BINARY AFTER_BINARY [RUNS] [--default-index]` (unchanged `index` calls, paired), `measure-symbol-ownership.sh BASELINE_BINARY CANDIDATE_BINARY CORPUS_REV [RUNS]` (minified Rust inputs up to 8000 functions, identical index required), `measure-shard-recovery.sh SNAPSHOT BINARY [RUNS]` (one damaged shard versus a full rebuild), all under `scripts/benchmarks/`.
- Depth comparison: `scripts/benchmarks/compare-depth.sh CORPUS [SAMPLES]` reports which share of Graphify's in-corpus calls, inherits, implements and imports xcalygraph also emits (dumped through the ignored `dump_edges` test), with sampled misses. Graphify output is a candidate list, never evidence of correctness.
- Precision samples for relation kinds without a compiler oracle (`runs`, `references`, `imports`, `mentions`, `queries`): `scripts/benchmarks/sample-precision.sh` builds a guarded release test binary and samples the 48 pinned corpora, xcalygraph and Graphify, taking the 50 lowest SHA-256 ranks per corpus, language, edge kind and confidence, with one pending row per sample in `adjudication.tsv` under `.cache/task192-manifests/run.*/`.

Agent benchmark (only when the owner asks for it):

- `scripts/benchmarks/run-agent-benchmark.sh [--run] [--runs N] CORPUS...` runs headless Codex per question in three arms (no tool, Graphify skill, xcalygraph skill), always `codex exec --json --ephemeral` with model `gpt-6-luna` at reasoning effort `max`. CORPUS is `xcalygraph`, `graphify`, a pinned public corpus (a subdirectory such as `bulletproof-react/apps/react-vite` names its question set with dashes) or a private corpus. Without `--run` it writes nothing and prints the planned invocations.
- Isolation: each arm gets a fresh HOME and CODEX_HOME that link only `auth.json` from `$CODEX_HOME` (default `~/.codex`), only that arm's skill, a fresh `git archive` copy of the corpus committed as its own repository, and no PATH entry that provides another arm's tool. The JSONL trace stays under `traces/`; corpus copies, homes and the binary copy are removed at the end.
- Status per answer: `correct` (expected path and symbol named), `wrong_symbol` (path only), `miss`, `error` (failed turn, missing usage or answer) or `leak` (a tool call ran another arm's tool in command position). `results.tsv` records status, tokens (input, output, reasoning), agent messages, tool calls, wall time and reasoning tokens.
