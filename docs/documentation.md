## Overview

xcalygraph is a single-binary CLI for AI agents. It turns any directory (code repository, server filesystem, document corpus) into a dense, agent-readable knowledge graph plus precomputed analyses, so an agent gets verified structural context with few tokens and little orchestration work. It ships with one compact agent skill that the binary installs and updates together with itself.

It is a clean-room rewrite of a selected subset of Graphify, without LLM calls, without visualization, without runtime dependencies and optimized for build speed, incremental updates and token efficiency of its output. Target blueprint: `docs/spec.md`; deferred features: `docs/deferred.md`.

License: MIT (`LICENSE`).

- Search also looks up related query-only forms (`validation`/`validate`, `token`/`tokenize`, `retrieval`/`get`) at half the original term's weight. Exact terms remain indexed and are never replaced; the higher contribution per query term is used.
- Query flags: `-C, --root PATH`, `-b, --budget N` (tokens, bytes / 3), `--json`, `--read-only`, `--index-dir PATH`, `-p, --path GLOB` (gitignore syntax, repeatable), `-l, --lang LIST`, `-k, --kind LIST`, `--exact`, `--no-tests`; `show` adds `-d, --depth N` and `--all`. One inclusion rule (`Filter::includes`, `src/app/query/mod.rs`) governs every stage: NAME resolution in all forms, `path` hops (induced subgraph), `impact` dependents, tests and run lines (traversal itself crosses excluded nodes), `show` tests and `map` module sections; `-k` limits symbols only, so files stay resolvable.
- NAME forms: `qualified.name` or `qualified::name`, a qualified suffix (`Store.Get`), `path:line` (innermost symbol containing the line), `path::name`, a file path, or a bare name.
- Query commands refresh the index first; `--read-only` never creates, probes or writes anything under the root, HOME or index base (also for a non-writable index) and exits 5 whenever a rebuild would be needed: index missing, sources changed, derived image corrupt, or another extraction, resolver or binary version.
- Exit codes: 0 answer, 1 runtime error, 2 usage error, 3 ambiguous NAME (candidates on stdout), 4 no match, 5 index missing or stale under `--read-only`.
- Usage errors print one stderr line `xcalygraph: <error>; run 'xcalygraph help'` and nothing on stdout. A reader that closes stdout early (`| head`) is not an error.

## Languages

Every language drops unqualified references to its builtins and prelude names, unless the file defines a function of that name at top level or in a module (a local definition shadows the builtin; methods of classes do not). Locals and parameters shadow every unqualified use of their name in their scope (Ruby: only bare names, since `foo(1)` calls the method). Member reads with a declared receiver type resolve to the member (`account.label`, method values like `read := rw.Read`). Overloads of one owner, including top-level functions of one module or imported module (Kotlin, C++, Swift, Dart), are told apart by argument count (trailing lambdas count as one argument; string defaults may hold commas); several overloads accepting the count are all targets, inferred. Signatures longer than 160 characters keep their whole parameter list with each parameter shortened to its label and name (`columns = …` marks a default), so the count survives. Base lists record their type argument count, so a base type named like a generic overload (`IRequest` and `IRequest<T>`, `Base` and `Base<T>`) resolves to the overload with that many type parameters.

## Installation and releases

- Install script: `scripts/utils/install.sh`, attached to every release as `install.sh`, resolves the latest release (or `--version X.Y.Z`), downloads the platform archive and `SHA256SUMS`, verifies the checksum, smoke-tests the binary and lets it run `install` (binary, skill, Claude Code link); `--no-skill` installs only the binary through an exclusively created temporary file beside the destination, preserves existing temporary entries and rejects directory targets; `XCALYGRAPH_INSTALL_DIR` and `XCALYGRAPH_RELEASE_BASE` (also `file://`) override target and source.
- Progress: `install` and `update` draw their phases on stderr when it is a terminal (`src/app/progress.rs`: spinner with elapsed time, download bar in eighth blocks with bytes, smoothed speed and remaining time, one line per finished phase with paths below HOME shown as `~`); otherwise nothing is drawn and the stdout result lines carry the facts.

## Output format

- Symbol lines are grouped under their file line and indented two spaces: `<line> <signature>`, or `<line> <kind> <name>` for symbols without a signature; `ctx` seeds append ` // <doc sentence>`.
- Relation lines: `<marker> <qualified name> <path>:<line>`; incoming edges cite the reference line, outgoing ones the target definition; edge kinds other than calls and type hierarchy are appended (`uses`, `imports`); a trailing `?` marks an inferred edge. `path` marks each inferred hop (inferred edge or reversed direction) and prefers the equally short path with fewer inferred hops; `impact` marks a dependent inferred unless a shortest chain to a target is all exact, so uncertainty carries to every later depth; `--exact` drops both, and `path` then never falls back to an undirected route.
- Budget: stdout never exceeds `3 x -b` bytes, including the truncation line `+<n> more` (space reserved), ambiguity candidate lists (at most 600 tokens) and `impact` run commands (reserved first, package-level form when the precise one does not fit); below one item the answer is `+<n> more` alone. Truncation by budget ends the output with `+<n> more`. Grouping never lets a lower-ranked hit displace a higher-ranked one: the best hits that fit are chosen first, then grouped.
- `--json` writes JSON Lines with the fields of `docs/spec.md` section 8; empty fields are omitted.

## Architecture

Single binary crate. Layers and modules under `src/`:

| layer | modules | responsibility |
|-------|---------|----------------|
| `cli` | `cli.rs` | argument parsing, help text, exit statuses |
| `app` | `app/` | one use case per command: workspace resolution, refresh pipeline, queries (`app/query/`) |
| `domain` | `domain/` | pure model: file types and roles, corpus records and change detection, facts, graph, tokenizer |
| `extract` | `extract/` | pure fact extraction: generic tree-sitter query engine (`engine.rs`), one language pack per grammar (`lang/`, queries in `queries/*.scm`), manifests |
| `resolve` | `resolve/` | pure global resolution of all facts to the symbol graph (module rules, resolution order steps 1 to 8, implementations, dispatch) and derived data (rank, module import graph, cycles, layers) |
| `infra` | `infra/` | parallel walk, scan and hashing, writer lock, index store (container, codec, fact shards, zero-copy `derived` file) |

`src/main.rs` wires the layers and owns process IO: stdout, stderr and the exit code.

Refresh pipeline: lock -> walk (`ignore` crate, parallel) -> stat diff against the file table (an unchanged `.h` whose C++ sibling appeared or vanished is reclassified, the only classification input outside a file; checked by binary search in the sorted file table) -> hash and classify candidates (parallel) -> extract changed files (parallel; a parser fault is isolated per file, which keeps its path and the file doc `! extraction failed`) -> rewrite only the affected fact shards -> resolve all facts -> write `derived` -> write file table and meta. Writers reject symlinked or hard-linked lock files; an existing regular lock is opened without creation or truncation and verified before use. The lock is advisory and cannot protect against processes that disregard it. An empty change set writes nothing. `derived` is rebuilt when content changed, when its header is invalid, or when it was written by another binary or resolver version; a checksum or content failure found by a query or `index` re-derives it once from stored facts. Equal headers and lengths do not suppress a write unless the existing image is byte-identical. When rebuilding `derived`, missing, corrupt or incomplete required fact shards are re-extracted from their source files; walk and read errors or content changes during extraction abort the update. Before changing shards, the writer invalidates metadata so interrupted updates force a rebuild instead of mixing generations. Each language query compiles lazily, only when a file of that language is extracted.

Freshness compares size and mtime together with device, inode and status-change time on Unix; both times must be outside the two-second racy window. Missing or unusable identity forces content-eligible files to be hashed; sensitive and oversized files remain path-only. This detects ordinary edits and replacements that restore mtime, but metadata cannot prove freshness if a filesystem repeats or rewinds its identity and status-change values, and a scan does not freeze concurrent source edits.

Index location: disposable by design (`src/app/workspace.rs`): `--index-dir`, else a nonempty `$XCALYGRAPH_INDEX_DIR`, else `<system temp directory>/xcalygraph-<user>` (new base mode at most 0700), so the operating system's temp cleanup bounds their number and repositories stay clean. No temporary writability probe is created: an existing shared index works even when its base cannot create entries. If implicit shared-index preparation or a required write fails because of its location, the index goes to `<root>/.xcalygraph/` with a notice to ignore it in git; explicit locations, source errors and lock contention do not fall back. Both implicit index locations are excluded from the walk. Read-only discovery writes nothing and can use a current local index when the shared one is absent, stale or unreadable. A lost index costs one full build; shards are extracted, deflated and written in parallel. Index files (`<index-dir>/<root name>-<hash>/`): `meta`, `files` (front-coded paths, stat, XXH3-128, role, file type), `facts/00..63` (varint-coded per-file facts referencing a shard-local string table, both sections deflated; shards are inflated in parallel when `derived` is rebuilt), `derived` (fixed-size records cast in place from the memory map: string table, files, symbols with rank (qualified names stored as a shared prefix string plus the name), forward and reverse CSR adjacency, modules, module import graph, externals, env sites, fields, type members, stale doc references, ambiguous names; search postings with per-field term frequencies as delta-varint pairs, decoded per query term), `git` (churn and co-change of the last 1000 non-merge commits, keyed by HEAD, written on the first `audit` after HEAD moves). Every file carries a header with magic, format version, kind and XXH3-64 checksum and is replaced by temp file plus rename.

Grammars are cargo features (`lang-go`, `lang-rust`; all on by default). Adding a language means a pack in `src/extract/lang/`, a query file and fixtures; the engine and resolver are shared.

## Build and test

- Toolchain: `rust-toolchain.toml` pins Rust 1.99.1 with rustfmt and clippy; rustup selects it inside the repository. `Cargo.toml` sets `rust-version` to the same release.
- Development builds: `cargo build` (debug profile); `xxhash-rust` alone uses optimization level 3 so full-index integrity checks stay fast, with debug assertions retained.
- Gate: `scripts/tests/test.sh` runs `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings` and `cargo test` with `RUSTFLAGS=-Dwarnings`; any finding fails the run. Below 2 GiB free disk space it runs `cargo clean` first and aborts if that is not enough. It first runs `scripts/utils/prune-cache.sh`.
- Lints: clippy denies `unwrap_used`, `expect_used`, `panic`, `todo` and `unimplemented` for all targets (`Cargo.toml`); tests return `Result` instead of unwrapping.
- Tests: unit tests next to the code in `#[cfg(test)]` modules; end-to-end tests of the binary (stdout, stderr, exit codes) in `tests/`.
- Golden fixtures: `tests/fixtures/languages/<id>/` holds sources whose extracted facts are compared with `<file>.facts`; `tests/fixtures/resolve/<case>/` holds small roots whose resolved edges are compared with `<case>.edges`. `XCALYGRAPH_BLESS=1 cargo test` rewrites the golden files; every changed line is checked against the fixture source before commit. A determinism test compares `derived` images built with 1 and 8 threads.
- Precision sampling: `XCALYGRAPH_SAMPLE_ROOT=<dir> cargo test --release sample_edges -- --ignored --nocapture` prints up to `XCALYGRAPH_SAMPLE_SIZE` (default 50) edges per kind and confidence, each with the reference line and the target signature, for checking against source (`docs/spec.md` section 12).
- Evaluation: `scripts/benchmarks/run-evaluation.sh [--no-upstream] [--set NAME] [CORPUS...]` builds the debug binary and answers every question of `scripts/benchmarks/questions/<corpus>.tsv` (default corpora: this repository, the upstream clone and hono from `research/corpora/`; private sets under `questions/private/`; columns question, expected `path::name`) and reports hit@5 of `find` (expected file among the first five results, `docs/spec.md` section 12), the same for the exact symbol, hit@5 of `ctx`, mean tokens per answer, the rg baseline (rg output for the two longest question words plus reading the expected file) and the upstream Graphify baseline. Both tools read the same verified source snapshot. Each run retains identities, questions, raw answers, stderr and misses under a new `.cache/evaluation/run.*/` directory; missing upstream extraction or a failed query aborts instead of producing a comparison score.
- Expected query refusals score as misses: xcalygraph no-match exit 4; Graphify ambiguous exit 3 and no-match exit 4. Graphify stdout and exit status are retained per question; runtime failures invalidate the run.
- Sealed evaluation labels: `scripts/benchmarks/questions/sealed/manifest.json` binds eight public source snapshots to 30 questions each. JSON Lines cases name required declaration locators with source/evidence hashes and acceptable alternatives; multi-location cases require every locator. Negative cases ask for exact symbols verified absent from their frozen sources. Prior corpus exposure and the same author's inability to blind itself are explicit; these labels measure retrieval of source locators, not an agent's final-answer correctness. The frozen xcalygraph source predates the new labels.
- Run sealed evaluation through the existing entrypoint: `scripts/benchmarks/run-evaluation.sh --set sealed --validate` checks sources, upstream graph, labels and evidence without querying or consuming final eligibility; `scripts/benchmarks/run-evaluation.sh --set sealed [CORPUS...]` records the first final observations. Later runs require `--phase development`; add `--budget N` to measure only one budget from the frozen manifest, while still measuring Graphify at 2000 and retaining the original manifest hash and exposure. Add `--reuse-graphify RUN` to reuse a completed run's raw Graphify answers after checking the manifest, source, case, command, exit and recalculated scores; each reused observation records its origin and output checksum. These are historical observations, not new independent runs; original runs without output checksums cannot prove that their retained bytes were never altered. Final and validation runs cannot use these options. A receipt under `.cache/evaluation/exposure/` consumes final eligibility at the first observation, including an interrupted run. Missing snapshots are reconstructed from local pinned Git archives; a different content identity fails explicitly.
- Sealed metrics: actual `find`/`ctx` text and JSON and Graphify answers at 200/600/1200 requested tokens; Graphify at 2000 also preserves the legacy asymmetric comparison. Positive reports separate file hit@5, complete definition coverage at five/anywhere, covered/required locations, the `multi` question family and all questions requiring multiple locations. For each budget, `workflow-text` and `workflow-json` select `find` for single-location or negative cases and `ctx` for multiple-location cases, with paired results against Graphify at 2000. This routing uses the known evaluation labels and does not measure an agent's ability to choose a command. Negatives report false-positive counts separately. Paired complete-answer counts and descriptive Wilson intervals accompany aggregates; actual bytes, estimated tokens (ceil(bytes/3)) and budget excess are recorded. Text groups can merge a file hit with its adjacent symbols, so JSON is authoritative for legacy file hit@5; exact declaration matching uses the same path/line/name criteria in both formats. Every subprocess retains stdout, stderr, exit code and wall time under a new `.cache/evaluation/sealed.*/`; report.json and per-question scores retain exposure and binary identity. `public-report.json` records aggregate results, hashes and prior exposure without local execution paths. The public `questions/sealed/observations.json` contains the initial aggregate metrics. No final agent-answer or statistical superiority claim follows from these locator metrics.
- Evaluator regression: `scripts/tests/test-evaluation-labels.sh` exercises the real binary, Graphify, pinned-source restoration, text/JSON definition matching, wrong-function rejection within the same file, partial multi-location answers, negative penalties, repeat-final refusal, focused budgets and checked baseline reuse in one exclusively new temporary repository.
- Corpus snapshots: `scripts/utils/prepare-corpus.sh ROOT SNAPSHOT_BASE [--graphify]` creates or verifies a content-addressed source copy and prints its path; `--verify SNAPSHOT_SOURCE` verifies an existing frozen source, metadata and graph without selecting the current working tree. Git roots include regular tracked and nonignored untracked files; other roots use `rg` enumeration. The identity records paths, SHA-256 contents and executable bits. Graphify reuse additionally verifies its installed package source/version, update mode and graph checksum. Snapshots live under `.cache/corpus-snapshots/`; old evidence is retained, and corrupted or incomplete artifacts cause an explicit failure. `scripts/tests/test-corpus-snapshots.sh` verifies real-tool reuse, change/add/remove/rename invalidation and corruption rejection in an exclusively new isolated test directory; it requires Graphify and `target/debug/xcalygraph`.
- Agent benchmark: `scripts/benchmarks/run-agent-benchmark.sh [--run] [--runs N] CORPUS...` plans headless Claude Code runs per question in three arms (no tool, Graphify skill, xcalygraph skill), each with its own temporary `HOME`; without `--run` it only prints the invocations. With `--run` it records success (the answer names the expected file), tokens, turns and wall time.
- Public corpora: `scripts/utils/sync-corpora.sh [NAME...]` checks out the commits pinned in `scripts/benchmarks/corpora.tsv` (name, URL, commit, languages) with depth-1 fetches into `research/corpora/`; benchmarks and precision sampling pick them up.
- Benchmarks: `scripts/benchmarks/run-benchmarks.sh [--upstream] [CORPUS...]` builds the release binary and reports per corpus: files, full build ms, peak RSS, warm freshness ms, single-file refresh ms, index KB and KB rewritten by a single-file change. Both tools use the same verified source snapshot; edits append a valid comment in an isolated mutable copy. `--upstream` adds `graphify update .` wall time, peak RSS and `graphify-out` KB, then its update time after the same change. Each run retains source identities and measurement artifacts under `.cache/benchmarks/run.*/`. Corpora: this repository, the upstream clone, the pinned public corpora under `research/corpora/` and private ones listed as `name<TAB>path` in the gitignored `scripts/benchmarks/questions/private/corpora.tsv`. Requires `hyperfine`, `jq`, `rsync`, `python3`; `graphify` for `--upstream`.
- Query compute: `scripts/benchmarks/measure-query-compute.sh ROOT QUESTIONS.tsv [SAMPLES]` uses a verified frozen source snapshot, isolated HOME and index, and the test profile. After two warmups it measures in-process `find` scoring and rendering and `show` name resolution and rendering, excluding process startup, freshness and index opening. Per-question wall-time median, p95 and maximum are retained with input and binary hashes under `.cache/benchmarks/query.*/`; macOS also reports calling-thread CPU time on `cpu` lines, separately from wall time. `XCALYGRAPH_BENCH_OPT_LEVEL=3` optimizes the project crate in the test profile, retaining debug assertions and the dependency settings; neither configuration represents an actual release binary.
- Symbol-section copy: `scripts/benchmarks/measure-symbol-copy.sh DERIVED` measures a repeatedly cached, single-thread copy of the derived index's symbol section and records its hash. This read-and-write comparison estimates a memory scale, not a strict query lower bound or sustained RAM bandwidth.
- Index validation: `scripts/benchmarks/measure-index-validation.sh SNAPSHOT BEFORE_BINARY AFTER_BINARY [RUNS] [--default-index]` builds an isolated index from a verified snapshot and alternates unchanged `index` calls between the binaries. `--default-index` measures default-location selection; otherwise it uses an explicit index path. It rejects differing output or changes to index contents, inode or mtime and retains input hashes, individual wall times and load under `.cache/benchmarks/index-validation.*/`.
- Shard recovery: `scripts/benchmarks/measure-shard-recovery.sh SNAPSHOT BINARY [RUNS]` alternates recovery of one damaged fact shard and derived image with fresh full builds of the same snapshot. It verifies recovered bytes and untouched shard metadata and retains input hashes, individual wall times and load under `.cache/benchmarks/shard-recovery.*/`.
- Depth comparison: `scripts/benchmarks/compare-depth.sh CORPUS [SAMPLES]` uses the same verified source snapshot for Graphify and xcalygraph, dumps every xcalygraph edge through the ignored `dump_edges` test and reports which share of Graphify's in-corpus calls, inherits, implements and imports xcalygraph also emits (matched by source file, line within one and target file; imports by file pair), with sampled misses for verification against source. Run evidence is retained below `.cache/depth/run.*/`. Graphify output is a candidate list, never evidence of correctness. Requires `graphify`, `python3`.
- Publication check: `scripts/audits/check-publication.sh [RANGE]` runs before every push and fails on tracked local-only files, absolute home paths and private names (extended regexes in the gitignored `scripts/audits/private-patterns.txt`) in the tree or message of each commit; RANGE defaults to the commits not yet on `origin/main`.
