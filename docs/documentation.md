## Overview

xcalygraph is a single-binary CLI for AI agents. It turns any directory (code repository, server filesystem, document corpus) into a dense, agent-readable knowledge graph plus precomputed analyses, so an agent gets verified structural context with few tokens and little orchestration work. It ships with one compact agent skill that the binary installs and updates together with itself.

It is a clean-room rewrite of a selected subset of Graphify, without LLM calls, without visualization, without runtime dependencies and optimized for build speed, incremental updates and token efficiency of its output. Target blueprint: `docs/spec.md`; deferred features: `docs/deferred.md`.

License: MIT (`LICENSE`).

## Command line

Implemented commands; the full target surface is `docs/spec.md` section 2. `xcalygraph help` is the syntax reference.

| command | budget | output |
|---------|--------|--------|
| `map` | 2500 | root line (files, symbols, files per language), then sections `modules` (40 largest modules at path depth max 3: files, symbols, top 3 symbols by rank), `entry`, `tasks` (`<task> <path>:<line> > <what it runs>`), `hubs`, `api` (`<operation> [METHOD /path] <path>:<line> < <handlers>`), `cycles`, `layers`, `ext`, `env`; the budget cuts the lowest-priority section first |
| `find TERMS...` | 600 | ranked symbols and files, one line each, grouped under their file |
| `ctx TERMS...` | 2000 | up to 5 seeds (with doc sentence) plus related symbols by personalized PageRank, grouped by file |
| `show NAME [--all]` | 1200 | card: header, signature, doc, members (`m`), field names (`f`), supertypes (`^`), implementations (`v`), incoming (`<`, call sites), outgoing (`>`), tests (`t`, `t2` through one caller), env reads (`e`), ambiguity notice (`!`) |
| `impact NAME... \| --diff [REV]` | 1500 | `~` changed symbols (from NAMEs, or from `git diff --unified=0 REV` plus untracked files; `sig` marks an exported signature change against the REV version, `new` a symbol absent there, `new N` a new file with N symbols, `removed` a vanished one), `< depth` dependents by reverse BFS over calls, uses, inherits, implements, references and queries up to `-d` (default 3), `t` tests reaching them, `r` run commands (Go `go test ./pkg -run '^(A\|B)$'` per package, Rust `cargo test -p crate -- names` per crate, whole package beyond 20 names, test files otherwise); sections capped at 15, 25, 15 and 8 lines, run commands never cut by the budget |
| `path FROM TO` | 400 | one line per hop (`.` start, `>` forward, `<` against edge direction); without a directed path the undirected one, marked `?` |
| `audit` | 2000 | sections `dead` (private symbols without incoming edges, excluding tests, entrypoints, generated code, implicit names, interface contracts, dispatch implementations and ambiguously referenced names), `unused` (exports referenced only from their own file; Go, Rust, TypeScript, JavaScript, Python), `cycles` (module import cycles), `stale` (doc links and backticked doc mentions of a missing path or unknown symbol), `drift` (env reads without definition, and runtime definitions from `.env.example`, compose or Kubernetes without read; a name written as a string literal in source counts as read through a wrapper; only when the root defines env variables), `assets` (asset files without incoming `references` or `imports`, lines `<path>`), `coupling` (source, config or manifest file pairs, at least one of them source, without a static edge that share at least 3 of the last 1000 non-merge commits at Jaccard 0.3 or more, commits touching over 50 files ignored, with the shared count), `hotspots` (10 source files by churn weighted by top symbol rank); lines `<name> <path>:<line>`, `a <-> b`, `<text> <path>:<line>`, `read\|defined NAME <path>:<line> undefined\|unread`, `<path> <path> <count>`, `<path> <N> commits`; 15 lines per section, then `+N more`; `! git unavailable` without git |
| `index [--drop]` | none | `files N changed C deleted D`; `--drop` deletes the index of the root |
| `install [--link claude]` | none | writes the embedded skill to `~/.agents/skills/xcalygraph/SKILL.md` plus `.version` (unchanged files untouched); `--link claude` creates `~/.claude/skills/xcalygraph` pointing there when absent and never replaces a foreign entry |
| `update [--check]` | none | latest GitHub release of the repository; when newer: downloads `xcalygraph-<version>-<os>-<arch>.tar.gz` and `SHA256SUMS`, verifies the checksum, replaces the running binary by rename and runs `install` with it; `--check` only reports; `XCALYGRAPH_UPDATE_URL` overrides the release metadata URL (also `file://`) |
| `version` | none | `xcalygraph <version>`, `index format <n>`, `skill <version>` or `skill not installed`, and one `!` line when the installed skill differs; aliases `-V`, `--version` |
| `help [COMMAND]` | none | syntax overview or one command with its flags; aliases `-h`, `--help`, `<command> --help` |

- Query flags: `-C, --root PATH`, `-b, --budget N` (tokens, bytes / 3), `--json`, `--read-only`, `--index-dir PATH`, `-p, --path GLOB` (gitignore syntax, repeatable), `-l, --lang LIST`, `-k, --kind LIST`, `--exact`, `--no-tests`; `show` adds `-d, --depth N` and `--all`.
- NAME forms: `qualified.name` or `qualified::name`, a qualified suffix (`Store.Get`), `path:line` (innermost symbol containing the line), `path::name`, a file path, or a bare name.
- Query commands refresh the index first; `--read-only` never writes and exits 5 when the index is missing or stale.
- Exit codes: 0 answer, 1 runtime error, 2 usage error, 3 ambiguous NAME (candidates on stdout), 4 no match, 5 index missing or stale under `--read-only`.
- Usage errors print one stderr line `xcalygraph: <error>; run 'xcalygraph help'` and nothing on stdout. A reader that closes stdout early (`| head`) is not an error.

## Languages

Every language drops unqualified references to its builtins and prelude names, unless the file defines a function of that name at top level or in a module (a local definition shadows the builtin; methods of classes do not). Overloads of one owner, including top-level functions of one module or imported module (Kotlin, C++, Swift, Dart), are told apart by argument count (trailing lambdas count as one argument; string defaults may hold commas); several overloads accepting the count are all targets, inferred. Signatures longer than 160 characters keep their whole parameter list with each parameter shortened to its label and name (`columns = …` marks a default), so the count survives. Base lists record their type argument count, so a base type named like a generic overload (`IRequest` and `IRequest<T>`, `Base` and `Base<T>`) resolves to the overload with that many type parameters.

## Installation and releases

- Install script: `scripts/utils/install.sh` downloads the latest release archive for the platform, verifies it against `SHA256SUMS`, places the binary in `~/.local/bin` and runs `xcalygraph install` (with `--link claude` when `~/.claude` exists).
- Release archives: `scripts/build/build-release.sh [TARGET...]` builds `dist/xcalygraph-<version>-<os>-<arch>.tar.gz` (binary, `LICENSE`, `THIRD-PARTY-LICENSES.txt` with the license files of every dependency from `cargo metadata`) and `dist/SHA256SUMS`.
- `.github/workflows/release.yml` builds darwin-arm64, darwin-amd64, linux-amd64 and linux-arm64 (static musl) on a `v*` tag and publishes them with `SHA256SUMS` as the release of that tag.

## Output format

- Symbol lines are grouped under their file line and indented two spaces: `<line> <signature>`, or `<line> <kind> <name>` for symbols without a signature; `ctx` seeds append ` // <doc sentence>`.
- Relation lines: `<marker> <qualified name> <path>:<line>`; incoming edges cite the reference line, outgoing ones the target definition; edge kinds other than calls and type hierarchy are appended (`uses`, `imports`); a trailing `?` marks an inferred edge.
- Truncation by budget ends the output with `+<n> more`. Grouping never lets a lower-ranked hit displace a higher-ranked one: the best hits that fit are chosen first, then grouped.
- `--json` writes JSON Lines with the fields of `docs/spec.md` section 8; empty fields are omitted.

## Architecture

Single binary crate. Layers and modules under `src/`:

| layer | modules | responsibility |
|-------|---------|----------------|
| `cli` | `cli.rs` | argument parsing, help text, exit statuses |
| `app` | `app/` | one use case per command: workspace resolution, refresh pipeline, queries (`app/query/`) |
| `domain` | `domain/` | pure model: file types and roles, corpus records and change detection, facts, graph, tokenizer |
| `extract` | `extract/` | pure fact extraction: generic tree-sitter query engine (`engine.rs`), one language pack per grammar (`lang/`, queries in `queries/*.scm`), manifests |
| `resolve` | `resolve/` | pure global resolution of all facts to the symbol graph (module rules, resolution order steps 1 to 8, implementations, dispatch) and derived data (rank, module import graph, cycles, layers) |
| `infra` | `infra/` | parallel walk, scan and hashing, writer lock, index store (container, codec, fact shards, zero-copy `derived` file) |

`src/main.rs` wires the layers and owns process IO: stdout, stderr and the exit code.

Refresh pipeline: lock -> walk (`ignore` crate, parallel) -> stat diff against the file table -> hash and classify candidates (parallel) -> extract changed files (parallel; a parser fault is isolated per file, which keeps its path and the file doc `! extraction failed`) -> rewrite only the affected fact shards -> resolve all facts -> write `derived` -> write file table and meta. An empty change set writes nothing. `derived` is rebuilt when content changed, when its header is invalid, or when it was written by another binary or resolver version; a checksum failure found when a query opens it re-derives it once. Each language query compiles lazily, only when a file of that language is extracted.

Index files (`<index-dir>/<root name>-<hash>/`): `meta`, `files` (front-coded paths, stat, XXH3-128, role, file type), `facts/00..63` (varint-coded per-file facts referencing a shard-local string table, both sections deflated; shards are inflated in parallel when `derived` is rebuilt), `derived` (fixed-size records cast in place from the memory map: string table, files, symbols with rank, forward and reverse CSR adjacency, modules, module import graph, externals, env sites, fields, type members, stale doc references, ambiguous names; search postings with per-field term frequencies as delta-varint pairs, decoded per query term), `git` (churn and co-change of the last 1000 non-merge commits, keyed by HEAD, written on the first `audit` after HEAD moves). Every file carries a header with magic, format version, kind and XXH3-64 checksum and is replaced by temp file plus rename.

Grammars are cargo features (`lang-go`, `lang-rust`; all on by default). Adding a language means a pack in `src/extract/lang/`, a query file and fixtures; the engine and resolver are shared.

## Build and test

- Toolchain: `rust-toolchain.toml` pins Rust 1.99.1 with rustfmt and clippy; rustup selects it inside the repository. `Cargo.toml` sets `rust-version` to the same release.
- Development builds: `cargo build` (debug profile).
- Gate: `scripts/tests/test.sh` runs `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings` and `cargo test` with `RUSTFLAGS=-Dwarnings`; any finding fails the run. Below 2 GiB free disk space it runs `cargo clean` first and aborts if that is not enough.
- Lints: clippy denies `unwrap_used`, `expect_used`, `panic`, `todo` and `unimplemented` for all targets (`Cargo.toml`); tests return `Result` instead of unwrapping.
- Tests: unit tests next to the code in `#[cfg(test)]` modules; end-to-end tests of the binary (stdout, stderr, exit codes) in `tests/`.
- Golden fixtures: `tests/fixtures/languages/<id>/` holds sources whose extracted facts are compared with `<file>.facts`; `tests/fixtures/resolve/<case>/` holds small roots whose resolved edges are compared with `<case>.edges`. `XCALYGRAPH_BLESS=1 cargo test` rewrites the golden files; every changed line is checked against the fixture source before commit. A determinism test compares `derived` images built with 1 and 8 threads.
- Precision sampling: `XCALYGRAPH_SAMPLE_ROOT=<dir> cargo test --release sample_edges -- --ignored --nocapture` prints up to `XCALYGRAPH_SAMPLE_SIZE` (default 50) edges per kind and confidence, each with the reference line and the target signature, for checking against source (`docs/spec.md` section 12).
- Evaluation: `scripts/benchmarks/run-evaluation.sh [--no-upstream] [CORPUS...]` answers every question of `scripts/benchmarks/questions/<corpus>.tsv` (default corpora: this repository, the upstream clone and hono from `research/corpora/`; private sets under `questions/private/`; columns question, expected `path::name`) and reports hit@5 of `find` (expected file among the first five results, `docs/spec.md` section 12), the same for the exact symbol, hit@5 of `ctx`, mean tokens per answer, the rg baseline (rg output for the two longest question words plus reading the expected file) and the upstream Graphify baseline (`graphify query` on a graph of a copy below `.cache/`). Misses are written to `.cache/evaluation/misses-<corpus>.txt`.
- Agent benchmark: `scripts/benchmarks/run-agent-benchmark.sh [--run] [--runs N] CORPUS...` plans headless Claude Code runs per question in three arms (no tool, Graphify skill, xcalygraph skill), each with its own temporary `HOME`; without `--run` it only prints the invocations. With `--run` it records success (the answer names the expected file), tokens, turns and wall time.
- Public corpora: `scripts/utils/sync-corpora.sh [NAME...]` checks out the commits pinned in `scripts/benchmarks/corpora.tsv` (name, URL, commit, languages) with depth-1 fetches into `research/corpora/`; benchmarks and precision sampling pick them up.
- Benchmarks: `scripts/benchmarks/run-benchmarks.sh [--upstream] [CORPUS...]` builds the release binary and reports per corpus: files, full build ms, peak RSS, warm freshness ms, single-file refresh ms, index KB and KB rewritten by a single-file change (on a copy below `.cache/`; the change appends a comment line valid in the file's language). `--upstream` adds the Graphify baseline on the same copy: `graphify update .` wall time, peak RSS and `graphify-out` KB, then its update time after the same change. Corpora: this repository, the upstream clone, the pinned public corpora under `research/corpora/` and private ones listed as `name<TAB>path` in the gitignored `scripts/benchmarks/questions/private/corpora.tsv`. Requires `hyperfine`, `jq`, `rsync`; `graphify` for `--upstream`.
- Depth comparison: `scripts/benchmarks/compare-depth.sh CORPUS [SAMPLES]` builds Graphify's graph on a copy of a pinned corpus (or `graphify` for the upstream clone) below `.cache/depth/`, dumps every xcalygraph edge through the ignored `dump_edges` test and reports which share of Graphify's in-corpus calls, inherits, implements and imports xcalygraph also emits (matched by source file, line within one and target file; imports by file pair), with sampled misses for verification against source. Graphify output is a candidate list, never evidence of correctness. Requires `graphify`, `python3`, `rsync`.
- Publication check: `scripts/audits/check-publication.sh [RANGE]` runs before every push and fails on tracked local-only files, absolute home paths and private names (extended regexes in the gitignored `scripts/audits/private-patterns.txt`) in the tree or message of each commit; RANGE defaults to the commits not yet on `origin/main`.
